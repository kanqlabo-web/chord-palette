# 引き継ぎ：チュートリアル（レベル）の作り方とコツ

チュートリアルを作る・直すときは、`HANDOFF.md` のあとにこのファイルを読んでください。

## 1. 考え方（ユーザーとの約束）
- 相手は「音楽にまったく触れてこなかった人」。読む人の頭に、知らない言葉がひとつも残らないようにする
- 1回で教えることは1つ。レベルをクリアすると、その機能が使えるようになる（アンロック）
- 説明は1〜2文。長い説明は嫌われる（「説明が長すぎる」と言われたことがある）
- 楽器にくわしくない人の言葉で書く。専門用語は使わないか、使うなら必ずその場で説明する
  - 作業用の名前や MIDI のファイル名は画面に出さない
- 絵文字は使わない。アイコンは `ico('名前',大きさ)`（SVG）
- 音を出すときは「ただ鳴らす」のではなく、伴奏スタイルで演奏する（ユーザーの指示）
- **パレットの大きさはレベルによって変えない**（ユーザーの指示）
  - レベル1・2で使わない伴奏の帯や BPM の場所も空けておく（`.accOff`）
  - 吹き出しは、マスの下の空いている所に出す
- 大きな変更は、まずベータ版（`tools/beta-src/js/05-tutorial.js`）で作る
  - OK が出たら、ファイルを丸ごと `tools/src/js/` へ移す

## 2. ファイルと主な部品
- `tools/beta-src/js/05-tutorial.js`（通常版は `tools/src/js/05-tutorial.js`）
  - `SLIDES`: レベル1・2のスライド
  - `MOOD` / `PRACTICE`: 雰囲気のつくり方（レベル3）
  - `L_KEY`: キー（レベル4）
  - `L_SLIDES.{long,tension,slash,flip,…}`: レベル5以降
  - `LEVELS`: レベルの一覧。各レベルは `{name, goal, unlock, chips, deck:()=>スライドの配列, noClear}`
  - `levelDeck(n)`: レベルのタイトル → 本編 → クリアの画面を組み立てる
    - レベル1はタイトルなしで、そのままレベル2へ続く
  - `TASKS`: 実際の画面で操作させる課題
  - `WHERE`: クリアしたあと、実際の画面で新しい機能の場所を光らせて説明する（`showWhere(n)`）
  - `EX`: お手本の進行（`exampleHTML(EX.名前)` で並べて表示、`listenBtn('名前')` で演奏）
- `tools/beta-src/js/03-ui.js`
  - `LV_MAX`（レベルの数）
  - `UL()`: いま使える範囲。自由モードは全部
  - `ULx()`: 解説中は、そのレベルの機能も使える
  - `presetLv()`: 進行ライブラリの進行が何レベルから使えるか
- 文節での改行: `tools/beta-src/js/09-phrase.js`
  - 日本語は文節で自動で改行するので、`<br>` は「意味の切れ目」にだけ入れる
- 見た目（`style.css`）: `.tut`（スライド）、`.coach`（吹き出し）、`.tc`（コードのチップ）、`.ex`（お手本の並び）、`.okcard`（アンロックの札）

## 3. スライドの書き方
- スライド＝オブジェクト1つ。項目は次のとおり
  - `html:()=>'…'`: 中身（毎回作り直すので、関数で書く）
  - `steps:n`: 1枚のまま「つぎへ」で段階的に見せる
    - 要素に `data-st="k"`（k 段目から出す）・`data-upto="k"`（k 段目まで出す）
    - `data-dl`（遅れ・秒）・`data-dur`（アニメの長さ）
  - `enter:()=>…`: 表示した直後に呼ぶ（チップを鳴らせるようにする `bindHear` など）。`onStep:k=>…` は段階が変わったとき
  - `coach:'種類'`: スライドを閉じて、実際の画面の上に吹き出しを出す
    - 種類: `place`（パレットからマスへ置く）、`play`（再生させる）、`mood`（雰囲気の実践）、`task`（`TASKS` の課題、`task:'名前'` を一緒に書く）、`weird`（わざと変な進行を聴かせる）
  - `last:true, btn:'はじめる', finish:()=>…`: 最後のスライドのボタンと動き
- 出てくる動き
  - `class="a" style="--dl:.6"` で、0.6秒後にふわっと出る
  - `.pop` は弾むように出る、`.floaty` はゆらゆら動く
  - 中身を上から順に、0.2〜0.4秒ずつ遅らせると読みやすい
  - アニメの途中は「つぎへ」が「スキップ」になる（`animEnd`）
- コードのチップ
  - `tc(コード,'役割のクラス',遅れ)`、`hearChip(コード,遅れ)`
  - `data-hear` が付いたものはタップで鳴る。鳴らせるスライドには「コードをタップすると鳴らせます」の一文が自動で付く
- お手本の進行
  - `EX.名前={degs:[度数…], roles:['T','S','D',…], groups:[{a:始まり,b:終わり,t:'ラベル',c:'色',row:0/1}], key?, style?, bpm?}`
  - `tutLoadEx` が、そのスタイル・テンポで演奏する
- 課題（`TASKS.名前`）
  - 項目: `{load:[最初に置くコード], style, bpm, guide, text:'やること', hint:'ヒント', check:()=>できたか, ok:'できたとき', ng:'おしいとき', keys?}`
  - 再生して1周すると、`check` の結果で ok か ng の吹き出しが出る

## 4. 新しいレベルを足す手順
1. `L_SLIDES` に、スライドの配列を作る（説明 → お手本 → 課題、の順が基本）
2. `LEVELS` に1行足す（`unlock` に、クリアで使えるようになるものを、一般の言葉で書く）
3. `03-ui.js` の `LV_MAX` を増やす。アンロックする機能が `UL()>=n` で開くように、使う側の条件をそろえる
4. 進行ライブラリの進行も解放するなら、`presetLv()` を合わせる
5. `WHERE[n]` に、クリア後に光らせる場所と一言を書く
   - 設定メニューの中なら `{menu:'要素のid', x:'…'}`、画面の要素なら `{t:()=>要素, x:'…'}`
6. ビギナーで新しくできるようになったことは、PRO でも同じものを作れるようにする（`tparall.js`）

## 5. コツ（これまでのやり取りから）
- 直されやすいのは、音楽の言い方の正しさ（ユーザーがかなり細かく直す）
  - 進行の名前（「王道進行」など）、雰囲気の名前、何小節の進行か（4小節か8小節か）
  - 載せる前に、名前とコードの並びを確かめる
- レベルより先の内容は出さない（例：王道進行の説明に E7 の話を入れない。それはレベル8の内容）
- 言葉は「BPM」より「テンポ」のように、やさしい方を使う
- チュートリアルの間は、いつも ピアノ＋ベース・キー C・PRO オフ（`openTutorial`）。終わったら `endTutorial` で元の状態に戻る
  - 新しく state の項目を触るなら、ちゃんと戻るか確かめる
- 実際の画面で操作させる所（coach）は、「何をすればよいか」を1文で書く
  - できたら「いいですね！」と、すぐ反応を返す（`TUT.wait` で状態を見張る）
- クリアの画面には、アンロックしたものを `okcard` で見せる。そのあと `showWhere` で、実際の場所を案内する
- 画面の大きさをいくつか変えて確かめる
  - 縦長：390×664、390×844、375×600
  - 横長：820 以上
  - 吹き出しや文字が、タイルやボタンに重なっていないか見る
- ユーザーはスクリーンショットで指摘してくる。どの画面のどの段階かを、`TUT.i`・`TUT.step` で特定して直す

## 6. 確認のしかた（Playwright）
- `python3 -m http.server 8765` のあと、ベータ版 `http://localhost:8765/beta/` を開く
- `startLevel(n)` で、そのレベルを始める
  - `#tutNext` を押し続けて、エラー（`pageerror`）がないか見る
  - 段階ごとにスクリーンショットを撮る
  - coach の課題は、`state.slots` を直接入れて `check()` が true になるかを見る
- `terr.js`（開いたときのエラー）、`ted.js`（PRO の編集画面）、`tparall.js`（PRO と同じ音か）も通しておく
