## 作業の流れ
1. clone: `git clone --depth 1 https://github.com/kanqlabo-web/chord-palette`
2. 手元で確認: リポジトリの直下で `python3 -m http.server 8765` → Playwright（`NODE_PATH=$(npm root -g) node tools/t*.js`）で `http://localhost:8765/`（`/beta/`・`/lecture/`）を開く
   - サーバーはターンをまたぐと止まることがある。止まっていたら起動し直す
3. 公開: `bash tools/deploy.sh [patch|minor|major] "コミットメッセージ"`
   - `tools/VERSION`（1行目が版数、2行目が日付）を上げて build.py で作り、commit・push する。省略時は patch
   - minor・major のときは `CHANGELOG.md` に1行足してから
   - コミットに付ける行は `COMMIT_TRAILER="..." bash tools/deploy.sh ...` で渡す
   - gh のログインはできないことが多いので、Pages の完了待ちはしない。github.io もこの環境からは開けないことが多い
4. **公開の前に `node tools/tparall.js` で「ALL SAME」を確かめる**（全19スタイルを、ビギナーと「PRO に取り込んだもの」で鳴らし比べる。ベータ版が対象）

## 確認用の道具（tools/）
- `mid.py` / `nd.py` / `dr.py`: MIDI の中身を小節ごとに書き出す（`python3 tools/nd.py ファイル.mid`）
- `tsty.js`: 全スタイルを鳴らしてエラーがないか
- `tallsty.js`: 全スタイルの音を JSON に書き出す（変更前後の比較用。ギター系・ロックなどは毎回少しランダムに変わる）
- `tbal.js`: バラード（ballade.mid と同じコード）を小節ごとに書き出す
- `tparall.js`: 全スタイルで、ビギナーと PRO に取り込んだものが同じ音になるか（公開前に必ず）
- `tpar.js`: ビギナーのバラードと、PRO でマイ演奏に取り込んだものが同じ音になるか
- `torn.js` / `trand.js`: 飾りの出方（いろいろな進行・ランダムな進行）、飾りが2音同時に鳴らないか
- `tvoic.js`: 右手の和音のはしが半音でぶつかる形がないか
- `ted.js`: PRO のパターン編集画面が開けるか
- `tcity.js`: シティポップ（Am・Em・F・C）の音
- `terr.js`: 開いたときのエラーだけ見る
- `tstall.js`: シティポップ＋ラッパ隊で4小節ぶん鳴らし、通常版・ベータ版とも例外が出ないか（ベータ版の関数名が本体と重なると再生が止まる）

## 決まりごと（ユーザーとの約束）
- **基本の考え**: 音楽にまったく触れてこなかった人が、作曲の第一歩を踏み出すためのアプリ（「うさぎの絵ならだれでも描ける」ように）。下手な曲をたくさん作ってほしい。たくさんの機能は基本ぜんぶおまけで、初心者がいちばん先
- 大きな変更は、まずベータ版（beta）に作る
- 返事は丁寧語（です・ます）。短い前置き＋見出し付きの箇条書き。絵文字は使わない（アプリの UI もベクターのアイコン）
- アーティファクトは作らない。GitHub への push は確認なしでよい
- **ビギナーでできることは、必ず PRO（マイ演奏）でも同じものを作れるようにする**（取り込むと鳴り方が同じになること。`tparall.js` で確かめる）。マイ演奏の形は壊れてもよいが、今までの演奏が新しいしくみで完全に再現できないなら NG
- **独自の機能を足すときは、先にユーザーに申請する**（ユーザーが「実装してかまわない」と言った範囲は除く）
- 名前・説明は、楽器にくわしくない一般の人にわかる言葉で（作業用の名前や MIDI のファイル名を画面に出さない）
- 使わなくなったもの・わかりにくくなったものは整理する（聴き比べ用の候補などを残さない。古い保存データは別名で置きかえる）

- 「弾き方」は、選んだ1つの音の弾き方（フォール・しゃくりなど）だけに使う

- 「オシャレ度」（「オシャレレベル」ではない）。再生のラベルは「テンポ」。大きな見出しは「LEVEL n」、文章の中は「レベルn」
- （ver 5.25.007、ユーザー判断）画面に「場面」は出さず「〜のとき」（「1小節のとき」「演奏するとき」）。消すボタン・確認は「削除」「もう一度押すと削除します」。ゴーストは「ゴーストノート」。閉じる・元に戻すは「とじる」「もとに戻す」（ひらがな）。編集の写しも「◯◯（自分用）」（この曲用はやめた）。全部／すべては「ぜんぶ」（名前の「すべての機能で始める」だけ残す）。読み込み中などの「…」は「……」。ステージの書き方はそのまま

## 演奏データのしくみ
- コード楽器のパターン（`ARPS`）のイベント = `[マス, 行[], 長さ, 強さ, 方向, 飾り, (nx用3つ), オクターブ, 鳴らす条件]`
  - マスは16分（1小節16マス）。小数も使えるが、PRO の取り込みでは整数に丸まる
  - 行: 0=左手根音 4=左手5度 5=左手8度 1〜3=右手 下・中・上 9=右手 4音目 6〜8=アクセント（右手＋12） 'd1'〜'd10'=メロディ行
    - 右手 4音目: 4音のコードは4つ目の音。3音のコードでは、同時に「右手 下」を弾いていないとき（分散）だけ「右手 中＋12」
  - 飾り: fall（フォール） up（1つ上の和音の音） scoop（しゃくり） nx（次のコードへ音階でつなぐ）
    nt / ntd / ntu（次のコードのいちばん上の音／その1つ下／1つ上）、刺繍音（dn dn2 su su2 cd cu dnr upr grc grs trl p0 pu pd）
  - オクターブ（e[9]）: ±12。鳴らす条件（e[10]）: step（上の音の動きが小さい・上がる） down（大きく下がる：長3度以上） same（同じ） move（同じでない） rise（上がる） dip（少し下がる：1〜3半音）
- 場面 `sit`: bar（1小節。2つなら交互、4つなら4小節ひとまとまり） bar3（3拍） halfA（前半2拍） halfB（3拍目から） beat（1拍） push（食い）
  - 場面のないパターンには、1小節の弾き方から自動で作る（autoScenes）
- マイ演奏（PRO）は `state.myArps` などに保存し、`rebuildMy()` で ARPS に入れる。取り込み（`newMy`）は ARPS からマイ演奏へ
  - 編集画面では同じ行の音は重ねられない（重なると前の音が切られる）。組み込みのパターンもこの形で書く
- 楽器2（コード2）は `withPart2()` で状態を入れ替えて同じ処理で鳴らす

## 主なしくみ（音の決め方）
- 和音の形（`chordNotes` / `voiceFor`）: 前の和音から近い形を選ぶ。真ん中の高さ（パターンの「右手の和音を置く高さの好み」でずらせる）から離れすぎない
  - 右手のいちばん上・下の音がとなりと半音でぶつかる形（FM7 の A C E F など）は選ばない。どうしても無理なときだけ、ベースと同じ音を右手から抜く
  - 同じ形のコードが半音・全音で動くときは平行移動。2音の刻みは半音でぶつからないようにする。内声は弱めない
- 音域は楽器ごとの絶対値（PRO のスライダー）。ビギナーはスタイルごとの値（`lhOff` など）
- メロディの補正: キーの外の音を含むコードだけ。借りてきたコード（同主調）では同主短調の音階で
- 今のコードの音階（`chordScaleOf`）: 飾り・つなぎの音はここから選ぶ
  - キーの中のコード → キーの音階、借りてきたコード → 同主短調
  - キーの外の長三和音・属7 → 解決先（4度上）への部分転調（次が短調なら和声的短音階）。例: C のキーで E7→Am なら G は鳴らさない
  - 減和音 → 半音上の和声的短音階、m7(♭5) → 全音下の自然短音階
- 飾り「次のコードの上の音」系（`ornPitch`）: 次のコードを食うとき・次のコードがないときは入れない。隣の音まで増2度になるときは入れない
- 1周で止めるとき、食う曲は食いのタイミングで締める
- 左右の広がり（スタイルの wide）: 弦楽器は交互、鍵盤楽器は低い音ほど左、ほかはまん中
- ホルンなど tie のパターン: 同じ高さが続いたら弾き直さずにつなぐ

## スタイルで覚えておくこと
- バラード: ballade.mid（F のキー・テンポ80・ピアノだけ）から作った。左手はベースの音1つ（G2〜F♯3）、1拍目に和音、1拍裏から8分で分散、4小節目だけ1オクターブ下で上がる
  - 飾りは8分が基本、16分2音は2小節に1回。小節の途中でコードが変わる前は入れない。条件は上の音の動き（MIDI の分析から）。5.25.002 から「次の上の音」そのものは先に弾かない（小節の頭で同じ音が重なって「ドドー」になるため）。上がるときは1つ上から、少し下がるときは1つ下から入る
  - PRO で同じものを作るときは、左手の音域を G2 からにする
- ボサノバ: クラベスの「ポクポク」（2小節：1小節目 2拍・3拍裏 ／ 2小節目 1拍・2拍裏・4拍）＋3拍目に弱いスネア。ドラムキットの音源にクラベス（MIDI 75）を入れてある
- 壮大: 弦楽器の合奏＋ホルン（同じ音はつなぐ）。音量は コード1・コード2 1.1・ドラム0.25・ベース0.75
- アニソン: 上もの（コード2）なし

## PRO のトラック画面など（5.24.000 でベータ版から通常版へ移した。今のベータ版は通常版と同じ）
- 伴奏の設定シート（#sheet）に「決定」はない。シートの中で選んだものはその時点で決定（✕・外側は閉じるだけ）。シートから開いた選ぶ画面（openPicker、PICK.inst）はタップで決定して閉じ、伴奏スタイルはシートも閉じる
- **複数の楽器（パート）**: `PARTN`（0=コード、1=コード2、2〜=`state.xtr[n-2]`）、`withPart(k,f)` でパートごとの状態（`PS`）を切りかえて鳴らす。チャンネルごとに 音量→左右（StereoPanner）→出力、響き（convolver）への送り。`state.mix[ch]={v,m,s,pan,rev}`
- トラックの種類: `'arp'`・`'arp2'`・`'x:ID'`・`'drum'`・`'bass'`。`xOf`・`patOf`・`setPatOf`・`partOf` で読み書きする
- **PRO のトラック画面**（`07-tracks.js`、ユーザーの手描きのイメージ図と GarageBand をもとにした DAW 風の画面。色はアプリの色（ライト／ダーク）に合わせる）: 伴奏の帯をタップすると開く
  - 上: ミキサー・戻す・やり直す・テンポ・閉じる。下: 大きな再生ボタン
  - 下の再生ボタン・BPM は、メイン画面の `.transport` を開いているあいだだけ移して使う（`tpIn`・`tpOut`）
  - 帯は食い・後ろ倒し（`effStarts`、鳴らすときと同じ決め方）の位置で区切る。区切りをドラッグすると、コードの並び（`chordLine`）の位置を拍＋食い（±16分2つ）に分けて、マス・マスの途中の変わり目・食いに書きもどす（`setChordLine`）。同じコードがマスの頭で続くところは1本の帯にまとめる
  - ミキサーのいちばん上（楽器の絵と音色の名前）をタップすると音色の一覧
  - 左: トラックの頭（M|S と楽器の絵＋名前）。楽器の絵をタップすると、そのトラックのミキサーが左から出る（音量・左右・ミュート・ソロ・コンプ・高音・低音・エコー・リバーブ・色・消す。名前は上で変える）
  - 右: 小節の番号とコード名（タップでコード編集）、コードごとに区切って役割の色（T・S・D）でぬった帯。帯の中には、その場所で実際に鳴る場面（`sceneAt`、鳴らすときの `sitVar` と同じ選び方）の弾き方を描く。帯をタップすると、その場面を選んだ状態で編集画面を開く（いつもの伴奏は自分用のコピーを作り、何も変えずに閉じたら消す）。ドラムは1本の帯（タップした小節の 1小節目／2小節目）
- **ミックス**: 楽器ごとの出口は 入口 → 低音（lowshelf 220Hz）→ 高音（highshelf 3.2kHz）→ コンプ → 音量 → 左右 → マスター、音量のあとからリバーブ・エコー（付点8分、テンポに合わせる）へ送る。`state.mix[ch]` に `pan・rev・echo・comp・hi・lo`。伴奏スタイルごとのミックスは `STYLE_FX`（ビギナーでもそのまま鳴る。`setStyle` で PRO のトラック設定にも写すので、ビギナーと PRO で同じになる）
- **PRO への取り込みは損失なし**: マイ演奏の音に、元の和音のまとまり（`g`）・順番（`k`）・飾りの生の値・`oc`・`when`・小数の長さを持たせる。小節の場面が違うものは `contNotes`。`tparall.js` で確かめる
- 見直し（ver 5.22.001）: 設定の並び（レベル→曲の設定→表示→ライブラリ→PRO→書き出し・セーブ→リセット）、右上の「Key」「楽器」を押せるように、パターン編集の再生ボタンを上へ・細かい設定を折りたたみ

## 講義版（lecture）
- 先生の端末で「部屋を作る」→ 部屋番号（4けた）とパスワード。受講者は `lecture/#r=部屋&p=パスワード` のリンク（QR）を開くとすぐ参加。先生が「LEVEL n を開放」すると受講者の `LVL` が上がる（アンロックの案内が出る）
- Firebase Realtime Database の REST＋EventSource。先生だけ匿名ログイン。データは `lectures/{部屋}-{パスワード}`（`lv`・`owner`・`m/{受講者}`=最後に見えた時刻）
- 設定は `tools/lecture-src/js/08-lecture.js` 先頭の `LECTURE_FB` だけ。空のあいだは BroadcastChannel で同じブラウザ内だけ動く。手順は `tools/LECTURE_FIREBASE.md`

## 保留中・これからのこと
- 講義版の Firebase の設定（ユーザーが設定する。apiKey とアドレスをもらえれば貼って公開）
- 楽器をまたいだ同じ高さの音（シティポップの電子ピアノとブラス、壮大の弦とホルンなど）は、重ねる意図の音として残している
- PRO のメイン画面で、マスの上の行（進行名・「コードを編集」）が狭いと2行になる
- バラード: 3小節目（B♭/D）などで、和音の形が MIDI と違う（MIDI はベースの音を右手のいちばん下に重ねる）。そのため出る飾りも MIDI と変わる小節がある
- ギターの押さえ方（guitarShape）では、まれにはしが半音でぶつかる形が残る（Bm(M7) など）

## 追記（前のセッションからの補足）

### シティポップ（citypop.mid・brass2.mid から）
- ドラム: citypop.mid の強さをそのまま（`M16({マス:MIDIの強さ})`、dyn 2）。4小節目のフィルの最後でクラッシュするので、次の小節の頭のクラッシュはなし（`crash0:false`）

### PRO で使える主な設定（ビギナーの再現用。足したら PRO にも出す）
- 食いの設定
  - 食う小節を「2小節目に入る時だけ」にする（`push2nd`）
  - 食って入った小節でも、頭の左手（根音・5度）は弾く（`pushKeepLH`）
- 音の高さ・形の設定
  - メロディ行の高さ（`melOct`）
  - 4音以上のコードのルートを省く（`noRoot`）
  - メロディをよける（`avoid`）
  - ギターの和音の形＝ボサノバのバレーコード（`bossaV`）
- リズムの設定
  - 16分で軽くハネる（`swing16`）
  - 人間っぽく揺らす（`loose`）
- バラードなどのために足した設定
  - 同じ高さの音が続くときはつなげる（`tie`、壮大のホルン）
  - ベースと重なる左手の低い音を弱めない（`lhFull`）
  - 右手の和音を置く高さの好み（`rhMid`）。右手の高さ（`rhShift`）とは別
  - 場面の「3小節目」「4小節目」（4小節ひとまとまり）
- 編集画面: 編集モード／選択モード（どちらも複数選択）
  - 音ごとに、長さ（1・半・4分の1マス）、高さ（1オクターブ下・上）、鳴らす条件（上の音の動き）、飾り
- 音域: 楽器ごと（コード・コード2・ベース）の絶対値。スライダーで「いちばん下の音〜1オクターブ」を選ぶ（`rhLo` など）

### 作業の注意
- **1行の中に `// コメント` を差し込むと、その後ろのコードが全部コメントになる。** 以前これで弦楽器とアコギの設定（`INST_FX`）が消え、シンセ音になった。`node --check` は deploy.sh が自動でするが、それでは見つからないので、実際に音色が鳴るかも確かめる（`tsty.js` の sets= に読み込む音源が出る）
- **ほかのセッションが同じリポジトリを同時に直していることがある。** 作業の前に `git pull` する（deploy.sh も、組み立ての前に `git pull --rebase` する）
- ソースは1行がとても長い。全体を読まず、`grep -n` で探して必要な行だけ見る（トークンの節約にもなる）
- ユーザーは PRO の編集画面のスクリーンショットで形を伝えてくる。マスの位置は「グリッドの幅 ÷ マス数」で、音の左端から読む。印の種類で飾りがわかる
  - 下向きの三角：下へ動く刺繍音
  - 上向きの三角：上へ動く刺繍音（右上の上向き三角だけなら「1つ上の和音の音へ」）
  - 点線のふち：次のコードへつなぐ・次のコードの上の音を先に弾く
  - 右上の斜線：フォール
  - 左はしの ↓・↑：1オクターブ下・上
  - しま模様：鳴らす条件つき（上の音の動きで鳴ったり鳴らなかったりする）
- 参考にした MIDI（citypop.mid、brass2.mid、okesutora.mid、ballade.mid、ipanema、イエス様が〜（ボサノバ）など）はリポジトリに入っていない。もう一度必要ならユーザーに送ってもらう
  - ipanema とイエス様が〜から作ったボサノバのピアノ（上もの）は、ボサノバをピアノなしにしたときに削除した
- 「構造（構想）だけ教えて」と言われたときは、作らずに案だけ出す
